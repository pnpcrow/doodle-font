# 컴패니언 표현 방식 비교 · 0.1.0

## 기존 구현과 새 구현

기존 구현은 미리 그린 프레임을 재생하는 방식이 아니다. `body.png`를 384×384로 읽어 28×28 격자에 입히고, 시간에 따라 격자와 벡터 눈을 움직이는 혼합 렌더러다. 색 변화에는 같은 크기의 색조용 텍스처를 하나 더 사용한다. 검증 GIF는 이 실시간 렌더링을 녹화한 결과일 뿐 앱이 재생하는 자산이 아니다.

벡터 구현은 같은 캐릭터의 몸과 말린 머리를 독립적인 3차 베지어 곡선으로 그린다. 홍조와 눈도 도형이다. 화면 크기·배율에 따라 네 단계의 곡선 세밀도를 선택하고, 오목한 머리 윤곽은 미리 삼각형으로 분할한다. 외곽에 물리 픽셀 한 개 폭의 안티앨리어싱을 적용한다. PNG/SVG를 비트맵으로 바꿔 붙이는 방식이나 프레임 이미지 목록을 사용하지 않는다.

두 방식은 `Motion`과 변형 함수를 공유한다. 8가지 상태, 시선이 고개보다 먼저 따라오는 동작, 원형·네모 변형, 색 변화, 임계 감쇠 스프링 전환과 움직임 줄이기가 동일하게 작동한다. 렌더러를 바꿀 때 동작의 시계·위치·속도를 초기화하지 않는다. 그림 자체가 다르므로 두 표현의 픽셀이 동일하지는 않다. Needle/생성 AI를 추가 호출하지 않는다.

## 앱에서 비교·선택

**화면 → 컴패니언 표현 → 나란히 비교** 또는 **설정 → 컴패니언 표현 → 나란히 비교**를 연다. 같은 시각의 같은 자세를 두 캐릭터에 전달하므로 커서 이동·상태·확대 배율을 공정하게 비교할 수 있다. 상태 선택, 64~384 크기 조절, 움직임 줄이기를 제공한다. 창이 작으면 최대 확대 크기도 줄인다.

**원본 그림 사용** 또는 **벡터 사용**을 누르면 비교 창을 닫고 설정을 `appearance.json`에 저장한다. 사용자가 비교 후 선택한 **벡터를 기본값**으로 사용한다. 렌더러 설정이 없는 이전 설치도 벡터를 사용하며 테마·움직임 줄이기는 그대로 유지한다. 명시적으로 저장한 원본 그림 선택은 다음 실행에도 유지한다. 비교 창에서만 두 렌더러를 함께 보관하고, 창을 닫으면 비교용 자원을 해제한다. 평소에는 선택된 렌더러만 준비한다. 벡터 선택은 원본 PNG의 디코딩·캐릭터 전용 텍스처 생성을 생략하지만, 선택 가능한 원본 PNG는 실행 파일에 계속 포함한다.

## 외형 판단

- 원본 그림: 생성 이미지의 은은한 명암과 질감을 유지한다. 확대하거나 크게 변형하면 이미지 외곽과 머리 격자의 굴곡이 드러난다.
- 벡터: 단색 면과 명확한 윤곽으로 보인다. 큰 원형·네모 변형에서도 말린 머리의 열린 부분과 외곽이 깨끗하다. 원본의 미세한 질감은 재현하지 않는다.
- 시간상 부드러움: 같은 동작 계산을 사용하므로 벡터라는 이유만으로 애니메이션 속도나 프레임 간 보간이 달라지는 것은 아니다.

## 측정 결과 · 2026-10-10

Windows, AMD Ryzen 7 8840U, Rust 1.98.1, release 빌드. 각 칸은 CPU 시간 중앙값 / 95백분위수(μs)다.

| 표시 크기 | 배율 | 원본 그림 | 벡터 |
|---|---:|---:|---:|
| 64 | 1× | 97.2 / 160.7 | 28.9 / 32.6 |
| 192 | 1× | 96.3 / 103.5 | 38.5 / 42.3 |
| 512 | 1× | 95.9 / 99.7 | 58.6 / 61.0 |
| 64 | 2× | 97.0 / 133.1 | 38.2 / 39.8 |
| 192 | 2× | 96.2 / 100.7 | 58.7 / 61.8 |
| 512 | 2× | 95.7 / 99.9 | 98.9 / 102.5 |

일반적인 작은 표시에서는 벡터의 준비 비용이 낮았다. 512 크기·2× 배율에서는 더 많은 곡선 점을 계산해 원본보다 약간 높았으며, 모든 크기에서 더 빠르다고 말할 수 없다. 두 방식 모두 한 캐릭터의 작은 비용이므로 앱 전체가 같은 비율로 빨라진다는 뜻은 아니다.

| 자원 | 원본 그림 | 벡터 |
|---|---:|---:|
| 캐릭터 전용 RGBA 텍스처 | 1,179,648 bytes (1.125 MiB) | 0 |
| 캐시한 좌표·인덱스·반지름 | 512 bytes | 25,520 bytes (약 24.9 KiB) |
| 초기 준비 중앙값(12회) | 23.43ms | 0.46ms |
| 64 크기·1×의 최대 정점 / 삼각형 | 1,842 / 3,360 | 456 / 660 |

작은 크기의 비용과 변형 윤곽을 기준으로 **벡터를 권장**한다. 원본 질감을 선호하면 원본 그림을 선택한다. 로컬 원자료는 `artifacts/companion-renderers/benchmark.json`, 같은 움직임의 네이티브 캡처는 `artifacts/companion-renderers/comparison.gif`에 보관한다.

## 재현 방법과 측정 범위

```powershell
cargo run --release --locked --bin compare_companion -- --bench artifacts/companion-renderers
cargo run --locked --features ui-qa --bin compare_companion -- --capture artifacts/companion-renderers
pwsh -File scripts/ui-qa.ps1 -CompanionOnly
```

벤치마크는 8가지 상태와 같은 커서 경로에서 미리 계산한 960개 자세를 사용한다. 120프레임 예열 후 두 방식의 실행 순서를 바꿔 가며 5회 측정한다. 크기 64/192/512와 화면 배율 1×/2× 각각에서 4,800개 표본의 중앙값·95백분위수 및 최대 정점/삼각형 수를 `benchmark.json`에 기록한다. 실행 파일을 최적화한 release 빌드로 비교한다.

시간에는 egui 컨텍스트 처리·그리기 명령 생성·삼각형 변환이 포함된다. GPU 명령 제출, 실제 화면 표시 시간, 프레임 간 대기, 캡처 파일 저장, 첫 실행 준비 시간은 프레임 측정에서 제외한다. 따라서 GPU FPS나 앱 전체 속도 향상을 나타내지 않는다. 초기 준비 시간에는 이미지 디코딩 또는 벡터 준비를 포함하지만 실제 GPU 업로드는 포함하지 않는다.

메모리 수치는 캐릭터 전용 비압축 RGBA 텍스처와 캐시한 좌표/인덱스의 용량이다. 앱 전체 RAM, egui 공용 글꼴 아틀라스, GPU 드라이버 부가 비용, 프레임마다 만드는 임시 도형과 할당기 부가 비용은 포함하지 않는다.

캡처는 제품과 같은 `paint()`를 네이티브 GPU 창에서 호출한다. 고정 60Hz 동작 시계로 3프레임마다 촬영해 16초/320프레임을 기록한다. 이는 시각 검증이며 실행 성능 측정이 아니다.

## 검증

곡선의 면적 보존과 머리의 오목한 영역, 렌더러 변경 전후 운동 연속성, 벡터의 전용 텍스처 미사용, 8가지 상태·세 크기·두 화면 배율의 유효한 좌표·인덱스·표시 영역을 검사한다. UI QA는 실제 클릭으로 비교 창 열기/벡터 채택/설정 저장/새 프로세스 복원/원본으로 복귀/작은 창의 표시 범위를 확인한다.

벡터 기본값 적용 후 자동 테스트 80개, 네이티브 UI 40개 시나리오와 `clippy --all-targets --features ui-qa -- -D warnings`를 통과했다. 그리기·후보 선택·API 연결 저장·처리 중 입력 잠금·플로팅 영역·내보내기까지 기존 기능을 포함한다. 버전은 0.1.0을 유지한다.
