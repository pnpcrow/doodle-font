# 검증 기록 · 2026-10-10

## 0.1.0 내장 AI 글자 형태 개선

- 기존 E2B Q4가 글자 전체 좌표를 생성하던 경로에서 A·B·가·한·あ·永를 동일 요청으로 실제 생성했다. 대부분 막대/꺾인 선/사각형으로 출력됐고, 굵은 획 요청에도 stroke 값은 2~5였다. 원 응답은 `artifacts/quality-before/`에 보관한다.
- 글자는 AI가 스타일 계획을 만들고 Rust가 정확한 공개 자형을 구성하도록 변경했다. Noto Sans CJK/Serif CJK 가변 OTF와 Single Day를 리비전·SHA256 고정으로 포함한다. Noto의 65,535글리프 가변 TTF는 현재 ttf-parser의 loca 파싱에서 윤곽을 읽지 못하는 현상을 확인해 CFF2 OTF로 교체했고 실제 윤곽·가변 굵기 검사를 통과했다.
- 같은 여섯 요청의 실제 로컬 결과를 시각 비교했다. 수정 후 모두 해당 글자로 읽히며 weight=650, width=100, roundness=80으로 일관된 스타일을 반환했다. 수정 전 약 20~32초, 수정 후 약 14~16초였다. 단일 PC의 순차 실행 결과이며 일반 성능 보장은 아니다. 원 응답은 `artifacts/quality-after/`, 전후 비교는 `artifacts/quality-comparison.png`이다.
- 실제 로컬 모델이 얇은 명조체 요청에 serif/weight=200, 손글씨 요청에 handwritten을 선택했다. 현재 그림 보존 요청은 최초 시험에서 glyph로 잘못 분류해 지시문과 예시를 보완했다. 재시험에서 current/stroke=70을 반환하고 원래 두 선의 좌표를 보존하며 굵기를 모두 70으로 바꿨다(`artifacts/quality-styles-v2/`).
- 윤곽선의 방향과 내부 빈 공간을 보관하는 레이어 형식을 추가했다. O의 내부 공간이 단색·컬러·비트맵 TTF 출력 후에도 비어 있는지 검사했다. 가변 굵기·너비·기울기·서체 변경, 한글/영문/가나/한자/문장부호 17개 예제와 분해 악센트, 한국어/일본어 曜의 지역 자형도 검증했다. 한글 11,172자 전체의 기본 자형 포함 여부를 검사했다. 알려진 자형이 없는 문자는 임의의 다른 문자로 대체하지 않고 오류를 표시한다.
- GPU UI 14개 시나리오 통과. 새 윤곽 후보의 표시·채택·출처 보존·실행 취소/다시 실행·저장 후 읽기를 포함한다. `artifacts/qa-ai-typography.png`에 채택 후 비교 화면을 보관했다.
- 최종 지시문으로 여섯 글자를 재생성해 모두 고딕/weight=650으로 생성되는 것을 확인했다(`artifacts/quality-final/`). 빌드와 동시 실행한 재시험은 약 15~25초였다. 실제 앱의 생성 버튼 → 로컬 모델 → 자형 후보/출처 저장 → 비교 화면 표시도 통과했다(`artifacts/qa-ai-typography-live.png`). 자동 테스트는 총 40개이며 모든 기능을 포함한 clippy 경고 검사도 통과했다.
- 후보 출처가 채택한 글리프와 출력 보고서로 전달되고 폰트 name 테이블에 OFL 전문이 들어가는 것을 검사했다. 앱 버전과 모델 파일은 기존 **0.1.0 / E2B Q4**를 유지한다. 손글씨 자형은 제공 글꼴의 범위/기본 굵기를 따르고, 그림문자는 기존 자유 도형 생성 경로를 유지한다.

## 0.1.0 AI 후보 표시 수정

- 실제 자동 저장 프로젝트에 A와 가의 AI 후보가 각각 1개 존재함을 확인했다. 그림 응답은 저장됐지만 기존 후보 UI가 속성 패널 맨 아래의 접힌 항목에 있었고, 완료 후에는 안내 문장만 표시됐다. AI 연결 탭에서는 그 속성 패널 자체가 보이지 않았다.
- 후보 생성 완료 시 현재 그림과 새 후보를 나란히 표시하는 비교 화면을 자동으로 연다. 하단 프롬프트와 속성 패널 상단에서도 저장된 후보를 다시 열 수 있다. 채택하면 편집 화면으로 돌아가며 실행 취소/다시 실행을 지원한다.
- 요청 종류를 결과 처리까지 보존하고, 그림 요청에서 설명만 반환되거나 빈/투명/작업 영역 밖의 그림이 반환되면 성공 안내 대신 오류를 유지한다. 후보 저장 제한 초과도 명시적으로 알린다. 새 작업을 시작하면 이전 상담 문장을 지운다.
- 자동 테스트 34개 통과. 새 검증에는 그림/상담 응답 구분, 비어 있는 응답·투명·숨김·작업 영역 밖 도형 거부가 포함된다. 모든 기능을 포함한 clippy 경고 검사 통과.
- 실제 GPU UI QA 13개 화면 통과. AI 연결 탭에서 모의 그림 응답 수신 → 후보 비교 화면 표시, 채택 버튼 클릭 → 편집 화면 복귀, 실행 취소/다시 실행, 저장과 후보 다시 열기를 검증했다. 설명만 반환된 경우에는 후보를 저장하거나 성공 화면을 열지 않는 것도 확인했다.
- 설치된 로컬 모델을 사용한 실제 UI 버튼 클릭 → 그림 생성 → 후보 저장 → 비교 화면 자동 열기도 통과했다(약 84초, 동시에 빌드 작업 실행). 화면은 `artifacts/qa-ai-candidate-live.png`에 보관한다. 생성된 그림에는 눈·입과 노란 도형이 있지만 원형이 왜곡되어 있어 생성 품질이 충분하다는 검증은 아니다.
- 사용자 프로젝트 사본에서 기존 A 후보의 미리보기를 확인했다(`artifacts/qa-ai-candidate-existing.png`). 원본 자동 저장 파일은 테스트 전후 SHA256이 일치한다.
- 버전은 **0.1.0**으로 유지한다. 모델의 글자 인식 정확도나 생성 품질을 개선한 변경은 아니다.

## 0.1.0 설치 화면 수정

- 앱 안에 로컬 AI 설치/검증/복구 버튼 추가. 다운로드 진행률·취소·재시도·부족한 파일·실제 설치 경로를 표시하고, AI 연결 화면에서는 2초마다 설치 상태를 다시 확인한다.
- Rust 설치기 테스트 7개 추가: 검증된 캐시 재사용, HTTP Range 이어받기, Range 미지원 서버 재시작, 끊긴 다운로드 재시도, 해시 불일치 시 기존 파일 보존, 취소 후 부분 파일 보존, 압축 경로 이탈 거부 및 실행기 의존 파일 진단. 총 31개 자동 테스트 통과.
- `scripts/verify-install-ui.ps1`은 격리 폴더에서 실제 버튼 클릭 → 모델 해시 검증 → 실행기 압축 해제 → 설치 완료 → 하단 AI 입력창 활성화를 검증한다. 사전 다운로드 파일을 하드 링크로 공유해 불필요한 4.3GB 재다운로드를 피하며, 운영 설치 폴더는 변경하지 않는다.
- 개발용 비최적화 빌드는 대용량 해시 검증이 느려 UI 검증 시간 제한에 걸렸다. 배포용 최적화 빌드로 같은 흐름을 검증했다. 설치 전/후 화면은 `artifacts/qa-install-missing.png`, `artifacts/qa-install-complete.png`에 보관한다.
- 현재 기본 모델 경로에 대한 Rust 진단 결과는 `installed: true`, `missing: []`이다. 사용자가 본 이전 창의 환경과 초기 표시 원인은 확정하지 않았으며, 설치 경로와 부족한 파일 표시 및 자동 갱신으로 확인 가능하게 했다.
- 버전은 사용자 요청에 따라 **0.1.0**으로 유지한다. 명시적인 버전 변경 요청 전에는 올리지 않는다.

Windows x64, AMD Radeon 780M, 약 52GiB 시스템 RAM. Rust 1.98.1 MSVC. 앱은 egui/eframe 네이티브 화면이며 WebView·Node·Python을 사용하지 않는다.

- 도메인/출력 16개, AI 연결/이미지/취소/잘못된 도형 응답 8개 테스트 통과.
- `cargo clippy --all-targets --locked -- -D warnings` 통과.
- UI QA 10개 화면을 실제 GPU에서 렌더링. 포인터 그리기·실행 취소·다시 실행·원본 보존·디스크 저장, AI 작업 중 포인터/편집 명령 차단 및 오류 후 편집 복귀 검증.
- 독립적인 Python fontTools에서 단색·COLR/CPAL·sbix·53,157 출력 글리프 TTF의 모든 테이블을 읽고 재저장/재파싱 통과. Python은 개발 검증에만 사용.
- 53,156개의 빈 작업 글리프(한글 + 한국/일본 한자) 자료: 생성 74.1ms, 폰트 출력 72.3ms, 896,112바이트. 부하 자료는 복잡한 도형이나 이미지가 없는 폭/지역별 자형 검증용이며 일반 작업 속도의 보장은 아니다.
- llama.cpp b11531 + EmbeddingGemma 2 Q8 실제 멀티모달 입력에서 768차원 벡터 확인. 웃는 얼굴에 대한 템플릿 유사도는 미소 0.78, 마음 0.66, A 0.65 순이었다.
- Gemma 4 E2B Q4가 같은 PNG를 보고 황토색 얼굴과 검은 눈/입을 한국어로 설명. 구조가 제한된 JSON으로 편집 가능한 컬러 얼굴 후보 생성도 확인. 생성 품질은 모델에 따라 달라지며 결과는 반드시 후보로 검토한다.
- 로컬 추론은 CPU 6스레드/8K 문맥으로 확인. 다른 빌드 작업과 함께 실행한 최초 상담은 약 65초, 구조를 제한한 벡터 후보는 약 60초였다. 추론 프로세스는 작업 종료 후 사라짐을 확인했다.

생성 자료는 `.gitignore`의 `artifacts/`에 보관한다. 화면은 `qa-ai-ready.png`, `qa-ai-busy.png`, `qa-ai-recover.png`에서 확인할 수 있다. 모델 가중치는 `%LOCALAPPDATA%/DoodleFont/ai`에 사전 설치했고 저장소에는 넣지 않았다. 설치 스크립트에는 원본 리비전, 배포 URL, SHA256을 고정했다.

외부 API는 실제 키 없이 모의 서버로 계약을 검증했다. 외부 앱의 색상/문자열 치환/지역별 자형 지원은 해당 앱의 폰트 엔진에 따라 달라진다. 앱은 GPU 추론 성능이나 모든 외부 앱의 이모지 교체를 보장하지 않는다.
