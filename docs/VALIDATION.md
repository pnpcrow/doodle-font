## 컴패니언 드래그 이동과 위치 저장 · 2026-10-11

- 왼쪽 버튼으로 컴패니언을 드래그할 수 있고 잡는 손 커서로 상태를 구분한다. egui의 이동 가능한 영역을 사용해 드래그 시작 시 위치가 뛰거나 누적 이동량만큼 계속 밀리지 않게 했다. 클릭과 드래그를 구분해 가벼운 클릭 반응 및 우클릭 메뉴를 유지한다.
- 위치는 `appearance.json`에 작업 영역 기준의 상대 좌표로 저장한다. 드래그 중에는 메모리에서만 갱신하고 버튼을 놓으면 저장하며, 창 크기를 바꿔도 상단·상태바를 제외한 범위 안에 둔다. 우클릭 메뉴와 설정의 **기본 위치로 되돌리기**는 저장 좌표를 지워 입력창 옆의 기본 배치를 복원한다. 기존 설정 파일에 좌표가 없어도 이전 배치를 사용한다.
- 실제 포인터 입력으로 벡터 캐릭터 이동, 재실행 후 작은 창에서 복원, 이미지 캐릭터를 화면 밖으로 끌었을 때의 경계 제한, 우클릭, 기본 위치 복원, 단순 클릭을 검증했다. 창 크기 변경과 입력창 펼치기 후 위치 유지, AI 처리 중 이동 잠금도 검사했다. 이동 전후 프로젝트 전체를 비교해 아래 캔버스에 획이 그려지거나 글리프가 바뀌지 않음을 확인했다.
- 위치 저장·창 크기 변경·잘못된 좌표 보정에 대한 회귀 테스트를 추가했다. 전체 **95개 자동 테스트**, 네이티브 레이아웃 **15개 시나리오**, 플로팅 입력창 **8개 시나리오**, UI QA를 포함한 전체 대상 clippy 검사를 통과했다. `artifacts/qa-layout-companion-drag-write.png`에서 옮긴 벡터 캐릭터와 입력창을 확인했다. 버전은 **0.1.0**을 유지한다.

## 둥근 창 모서리와 전체 화면 전환 · 2026-10-11

- 일반 창은 Windows 11 DWM의 `DWMWCP_ROUND`, 최대화·전체 화면은 `DWMWCP_DONOTROUND`를 사용하고 복원 시 다시 곡률을 적용한다. 화면 내부 패널을 둥글게 그리는 대신 실제 창의 합성 속성을 설정한다. 같은 상태에서는 속성을 반복 설정하지 않는다. 적용 기준은 [Microsoft의 둥근 창 모서리 문서](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-rounded-corners)를 따른다.
- DWM 속성을 지원하지 않는 Windows에서는 8 논리 픽셀 반경의 네이티브 창 영역을 사용한다. 크기·화면 배율이 바뀌면 영역을 갱신하고 최대화·전체 화면에서는 영역을 제거한다. 최소화 중에는 갱신하지 않으며 Windows에 전달한 영역의 소유권을 유지해 핸들 누수를 방지한다.
- Windows 빌드 26300에서 실제 최대화·복원·전체 화면·복원·크기 변경을 실행하고 DWM 속성을 운영체제에서 다시 읽어 확인했다. 호환 경로도 별도 시나리오에서 강제 실행해 네 모서리가 잘리고 네 변의 중앙은 보존되는지, 확장 상태에서는 영역이 완전히 제거되는지 확인했다. Windows 10 실기기 및 다른 배율의 모니터 간 이동은 이번 검증 범위에 포함하지 않는다. 프레임버퍼 스크린샷은 DWM 합성 뒤의 외곽 곡률을 보여주는 자료가 아니다.
- 전체 **94개 자동 테스트**, 레이아웃 네이티브 QA **12개 시나리오**, UI QA를 포함한 모든 대상의 clippy 검사를 통과했다. 버전은 **0.1.0**을 유지한다.

## 크롬리스 창과 커진 프로젝트 정보 · 2026-10-11

- 기본 Windows 제목 표시줄을 제거하고 앱 상단에 창 제어를 통합했다. OS 창 제목·아이콘은 작업 표시줄과 창 식별용으로 유지한다. 프로젝트 이름은 15→22, 패밀리는 11→15 논리 포인트로 키웠으며 프로젝트·화면·내보내기 메뉴는 탭 줄 오른쪽으로 옮겼다. 긴 이름도 창 제어 버튼과 겹치지 않으며 전체 이름은 툴팁으로 확인한다.

## 프로젝트 편집·탭·템플릿 및 사이드바 정리 · 2026-10-11

- 프로젝트 메뉴의 기본 `CloseOnClick` 동작 때문에 이름 입력칸을 누르면 패널이 닫히고 기존 이름이 유지되는 것을 실제 포인터·키보드 QA로 재현했다. 프로젝트 정보는 바깥 클릭으로 닫는 일반 팝업으로 변경했다. 이름과 폰트 패밀리를 입력·저장하고, Esc/바깥 클릭으로 닫은 뒤 다시 여는 동작을 검증했다. 이전 QA는 입력칸이 표시되는지만 확인했으며 이번에 실제 편집 검사를 추가했다.

## AI 설정 간소화와 상태바로 접히는 어시스트 · 2026-10-11

- 그림 분석·생성 AI를 사용 안 함/로컬 AI/OpenAI 호환/Anthropic 호환으로 정리했다. 새 환경은 사용 안 함이며 기존 저장된 선택과 API 키는 유지한다. 사용 안 함에서는 준비 상태 판정과 공통 실행 경로 모두에서 생성·입력 판단 호출을 차단한다.
- 입력 판단은 `내장 판단 AI 사용` 체크 하나로 바꾸고 모델 설명과 복구는 접었다. 체크를 켤 때 Needle이 없거나 로컬 AI로 선택을 바꿀 때 Gemma가 없으면 기존 설치기를 자동 실행한다. 이미 설치됐다면 재설치하지 않으며, 단순 재실행이나 화면 갱신으로 설치를 반복하지 않는다. 실패·취소 후에는 명시적인 재시도를 제공한다.
- API 주소·모델 이름·키와 저장/현재 주소의 키 삭제/연결 테스트는 `연결 설정`을 펼칠 때 표시한다. 연결 테스트는 동일한 API의 텍스트 경로에 `Reply with OK.`만 보내며 최대 출력 32토큰, 20초 제한을 둔다. 프로젝트·그림·Needle을 사용하지 않고 HTTP 오류 본문이나 키를 화면에 표시하지 않는다. 연결 성공은 텍스트 응답 검증이며 이미지 지원이나 그림 품질을 보장하지 않는다. 외부 유료 API는 이 작업에서 호출하지 않았다.
- 스타일 입력·생성은 별도의 `생성 테스트` 창으로, 프로젝트 이름·폰트 패밀리·자동 저장 위치는 상단 프로젝트 메뉴로 옮겼다. 생성 결과의 후보 비교·명시적 채택 동작은 유지한다.
- 입력창은 0.28초 동안 상태바 버튼 위치로 축소·이동·페이드되고, 접힌 뒤에는 UI 영역을 만들지 않아 아래 캔버스에 입력할 수 있다. 상태바에서 다시 펼치며 컴패니언의 크기와 위치는 유지한다. 설정 진입 시 자동으로 접고 움직임 줄이기에서는 즉시 전환한다. 변환 중에는 입력창 편집을 막아 그려진 위치와 입력 위치가 어긋나지 않게 했다.
- 설정 관련 네이티브 UI 18개 시나리오를 확인했다. 네 가지 선택/기본 꺼짐/꺼짐 후 키 보존, 작은 라이트 창, 연결 정보 접기/펼치기, 모의 API 성공·401 오류, 생성 테스트 창, 프로젝트 메뉴, 축소 중/완료 화면, API 키 입력·자동 저장·재실행·삭제·삭제 후 재실행을 포함한다. Needle·Gemma 자동 설치는 사용자 모델 파일을 변경하지 않는 별도 폴더에 검증 캐시를 하드링크하고 실제 설치·해시 검증·완료 표식을 확인했다. 추가 다운로드 없이 두 설치가 각각 한 번만 실행됐다.

## Windows에서 TTF·OTF를 읽지 못하는 오류 · 2026-10-11

- 기존 출력 6종(TTF·OTF × 단색·컬러·비트맵)이 Windows `AddFontMemResourceEx`와 `AddFontResourceExW`에서 모두 거부되는 것을 재현했다. 시스템 Arial은 같은 검사에서 읽혔다. 기존 Rust 파서·fontTools·브라우저 로드 성공만으로는 Windows 설치/미리보기 호환성을 확인할 수 없었으며 이 검증 범위를 보완했다.
- 공통 원인: BMP용 cmap format 4가 없었다. Unicode 0/3 및 Windows 3/1 레코드를 추가하고 전체 유니코드용 format 12와 표시 선택자용 format 14를 유지했다. format 4의 65,535바이트 한계를 위해 델타 구간과 글리프 배열을 최소 크기로 조합하며, 표현 불가능한 경우 잘린 표 대신 분할 출력을 안내한다. 이모지만 있는 폰트에는 NUL→.notdef 매핑만 추가해 Windows CFF 로더의 비어 있지 않은 BMP 구간 요구를 만족한다. 표시 글자나 글리프 ID를 추가·변경하지 않는다.
- OTF 고유 원인: CFF `CharstringType=2`를 긴 정수 표현으로 기록하면 Windows가 거부했다. 숫자를 표준의 짧은 정수 표현으로 기록하면 읽혔으며 오프셋 피연산자는 재배치 길이가 안정되도록 고정 길이를 유지한다. 빈 글리프만 있는 TTF는 길이 0인 glyf 테이블도 거부되어 .notdef에 빈 헤더·명령 길이 12바이트를 기록했다. 각 원인은 별도 파일 변형으로 분리 검사했다. 진단 자료는 `artifacts/font-compat-before/`에 보관한다.
- Windows용 앱은 TTF·OTF 생성 시 실제 Windows 메모리 글꼴 로더를 호출한다. 검사 글꼴은 현재 프로세스에만 잠깐 존재하고 즉시 해제되며 시스템에 설치하지 않는다. 로드 실패 시 출력 전 검사와 저장이 오류로 끝나며 잘못된 파일을 새로 쓰지 않는다.
- 새 회귀 검사: 희소·연속·비연속·큰 글리프 ID·BMP 경계의 매핑 왕복, format 4 길이 초과 오류, 두 Unicode 표의 일치 및 표시 선택자, Windows의 메모리/파일 로드 18조합(기본·공백만·이모지만 × TTF/OTF × 단색/컬러/비트맵). 한국어 임시 파일명도 사용한다. CFF의 65,535개 글리프 지원도 실제 Windows 로더 검사를 통과한다. ttf-parser 0.25.1의 format 4 배열에서 32768 이상의 ID를 음수로 취급하는 동작은 부호 없는 독립 디코더 및 fontTools 비교로 보완했다.
- `verify --large`와 `scripts/verify-font-formats.py`로 일반 12개 및 대규모 4개 파일을 독립 검사했다. 단색·컬러·비트맵의 TTF/OTF 6개와 53,157개 출력 글리프의 대규모 TTF/OTF 2개는 Windows 파일·메모리 로드 모두 통과했다. 대규모 자료는 빈 글리프와 지역별 치환용이며 복잡한 그림의 처리 성능을 대신하지 않는다. 브라우저에서도 일반 TTF·OTF·WOFF·WOFF2 12개가 모두 로드됐다. 결과는 `artifacts/verification/`에 있다.
- 대규모 자료는 글리프 순서를 뒤집어 32768 이상 ID를 가진 비연속 매핑과 format 4 글리프 배열도 검사한다. 네이티브 UI의 포맷 선택·출력 전 검사·작은 창 5개 시나리오 및 모든 대상·UI QA 기능을 포함한 clippy 경고 검사를 통과했다.
- 전체 자동 테스트 **88개**를 통과하고 `scripts/package.ps1`로 **0.1.0** 배포용 실행 파일과 SHA256을 갱신했다.
- 참고 규격: [Microsoft cmap](https://learn.microsoft.com/en-us/typography/opentype/spec/cmap), [Adobe CFF](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5176.CFF.pdf), [Windows 메모리 글꼴 로더](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-addfontmemresourceex). 앱 버전은 **0.1.0**을 유지한다. 이전 출력 파일은 프로젝트에서 다시 내보내야 한다.

## AI 후보의 자연스러운 비율과 좌우 균형

- 기존 공통 안내가 왼쪽 여백에 맞추도록 지시하고, 내장 자형 엔진도 가로 폭이 넘으면 가로 좌표만 압축하던 원인을 수정했다. 새 후보는 실제 보이는 획의 경계를 기준으로 선택한 글자 폭 안에서 좌우 여백을 균등하게 맞춘다. 배치 과정에서는 크기·획 굵기·세로 위치를 바꾸지 않는다. 자연스러운 비율이 최소 여백 안에 들어가지 않으면 폭·스타일 조정을 안내한다.
- 내장 AI와 두 API 제공자에 대상 텍스트의 기본 자형에서 산출한 참고 폭·높이·상하 위치를 같은 좌표로 전달한다. 참고 치수는 스타일 선택을 제한하는 강제 규격이 아니며, 가이드 한계선에 닿도록 확대하거나 가로세로를 따로 변형하지 않도록 명시했다. I/M의 서로 다른 폭, 소문자·구두점 크기, g/j/p/q/y의 하강 획을 구분한다. 내장 스타일 판단은 별도 폭·자간 요청이 없으면 width=100, tracking=0을 선택하도록 안내한다. 화면과 AI 참고 이미지에는 양쪽 최소 여백선이 함께 표시된다.
- 회귀 검사: 세 글꼴 계열의 좌우 균형·대문자 높이·소문자·하강 획, 폭 변경 시 크기와 기준선 보존, 사용자 요청 폭 비율 유지, 과도하게 좁은 폭에서 압축 대신 오류, API 다중 레이어의 상대 위치·획 굵기 보존, 글자별 참고 치수 및 양쪽 가이드 픽셀을 확인했다. OpenAI·Anthropic 호환 요청은 모의 서버로 지시문과 반환 후보의 동일한 배치를 확인했다. 외부 유료 API를 실제 호출하거나 모든 스타일의 시각적 품질을 보장한 검사는 아니다.
- 실제 설치된 Gemma 4 E2B로 A·I·M·H·x·g·한을 생성했다. 7건 모두 폭 100·자간 0을 선택하고 좌우 균형을 유지했다. A/I/M의 그림 폭은 각각 약 509/95/522로 달랐고, x는 대문자보다 작으며 g의 하강 획은 기준선 아래에 남았다. 약 11.1~13.4초/건이며 이 장치에서의 사례 측정이다. 원 응답·PNG·가이드 포함 PNG는 `artifacts/layout-balanced-live/`, 시각 검토용 모음은 `comparison.png`에 있다. 실행: `cargo run --bin verify_quality -- artifacts/layout-balanced-live --layout`.
- 네이티브 UI의 `ai-layout`, `ai-typography`, `ai-typography-live` 세 시나리오로 실제 g의 기준선/양쪽 가이드, 후보 표시·채택·실행 취소·다시 실행, 실제 내장 AI의 굵은 A 생성을 확인했다. 화면은 `artifacts/balanced-ai-layout.png`, `balanced-ai-typography.png`, `balanced-ai-typography-live.png`에 보관했다. 버전은 **0.1.0**을 유지한다.
- 전체 자동 테스트 **83개** 및 모든 대상·UI QA 기능을 포함한 clippy 경고 검사 통과.

## 하단 AI 창 플로팅 및 스크롤 수정

- 하단 플로팅 창과 별도로 있던 `ai-space` 고정 패널을 제거했다. 기존 패널은 응답 유무와 후보 수에 따라 112~292 논리 픽셀의 높이를 차지하며 작업 영역을 줄였다. 이제 화면 위에 겹치는 `Area`만 사용하므로 AI 활성화·긴 메시지·접기/펼치기로 캔버스 크기가 변하지 않는다.
- 응답 본문은 최대 120 논리 픽셀(작은 화면에서는 화면 높이의 18% 이내), 입력 본문은 56 논리 픽셀로 제한했다. 각 영역이 독립적으로 스크롤되며 응답에는 줄바꿈과 텍스트 선택을 적용한다. 응답 배경과 입력 테두리를 분리하고 고정 폭 스크롤 막대를 사용한다. 접기는 헤더만 남기며 펼치면 입력과 응답을 다시 표시한다.
- 실제 GPU UI 검증 5개 통과: 기본 1480×940 및 최소 1120×760 창에서 AI가 준비되기 전/후, 응답 80줄/입력 60줄, 접기/펼치기의 캔버스 좌표와 크기가 같은 것을 검사했다. 마우스 휠로 각각 실제 스크롤 위치가 변하는지, 창 밖으로 넘치지 않는지, 그림에 입력이 통과하지 않는지도 검사했다. 기존 AI 처리 중 잠금·오류 후 편집 복귀·후보 채택 시나리오도 통과했다.
- 실행 명령은 `pwsh -File scripts/ui-qa.ps1 -FloatingOnly`이며 결과는 `artifacts/qa-ai-floating.png`, `qa-ai-floating-small.png`에 보관한다. 응답은 레이아웃 검증용 모의 텍스트이고 실제 모델이나 외부 API를 호출하지 않았다. 모든 기능을 포함한 clippy 경고 검사 통과. 앱 버전은 **0.1.0**을 유지한다.

## API 연결 정보 자동 저장

- API 키뿐 아니라 선택한 제공자·API 주소·모델 이름이 매 실행마다 초기화되던 문제를 수정했다. 제공자별 연결 설정과 제공자·주소별 API 키를 프로젝트 밖의 `ai-connections.dat`에 함께 암호화해 저장한다.
- Windows DPAPI의 현재 사용자 범위와 `CRYPTPROTECT_UI_FORBIDDEN`을 사용한다. 실제 Windows에서 비밀번호·지문·인증 대화상자 없이 암호화/복원이 성공했다. 앱별 격리 저장소는 아니며 같은 계정의 다른 프로그램까지 막는 기능으로 설명하지 않는다.
- 입력 후 600ms가 지나면 자동 저장한다. 명시적 저장 버튼, AI 실행 전과 정상 종료 시 아직 저장하지 않은 변경의 저장, 현재 주소 키 삭제를 제공한다. 저장 실패는 화면에 표시하며 기존 파일을 보존한다. 복원 오류만으로 파일을 덮어쓰지 않으며 평문 저장으로 대체하지 않는다.
- 새 자동 테스트 5개 통과: 실제 DPAPI 암호화/다시 읽기와 평문 부재, 제공자·주소별 키 구분 및 삭제, 손상 파일 보존과 오류 메시지 내 키 노출 방지, Windows 파일 잠금으로 교체 실패 시 이전 키 유지/임시 파일 정리/재시도, 과대 파일 거부. 전체 자동 테스트 **52개**, 모든 기능을 포함한 clippy 경고 검사 통과.
- `scripts/ui-qa.ps1 -ConnectionsOnly`로 실제 네이티브 앱 프로세스 4회 실행을 검증했다. 포인터로 키 입력칸 선택 후 테스트 키 입력 → 타이머 자동 저장 → 앱 종료/재실행 후 같은 제공자·주소·모델·키 복원 및 AI 준비 → 삭제 버튼 클릭 → 다시 실행해 삭제 유지. 프로젝트에 키가 포함되지 않는 것도 검사했다. 실제 API 키와 외부 서비스는 사용하지 않았다.
- 화면은 `artifacts/qa-connections-write.png`, `qa-connections-restored.png`, `qa-connections-delete.png`, `qa-connections-empty.png`이며 키 마스킹·저장/삭제 버튼·설명문을 확인했다. 버전은 **0.1.0**으로 유지한다. 판단 모델 대안은 공식 자료 조사만 수행했으며 속도·RAM·한국어 명령 정확도를 실측하거나 설치/교체한 것은 아니다.

## 공통 입력 판단 옵션과 Gemma 단독 실행

- 내장 생성 경로에서 EmbeddingGemma 추론·768차원 응답·참고 그림 비교를 제거했다. 설치 목록도 Gemma 본체/이미지 인코더와 llama.cpp만 요구하며 약 3.43GB이다. 기존 설치 파일은 재사용하고 예전 임베딩 파일은 자동 삭제하지 않는다.
- Needle 3를 로컬/OpenAI 호환/Anthropic 호환에 공통으로 적용하는 별도 선택 옵션으로 추가했다. 기본 꺼짐이며 설치/복구·설정 저장은 생성 모델과 독립적이다. 약 36.9MB의 모델/실행기는 공식 리비전 `2ae11323dc000f5e70c49f7403efa6af12ba9e67` 및 SHA256으로 고정했다.
- 입력 판단 → 실행 전 검사 → 제한된 편집 후보 또는 원문을 선택한 생성 AI로 전달하는 경로를 검증했다. 판단 모델에는 프롬프트만 전달하고 모드·대상 글자·제공자·이미지 동의·API 키를 바꾸지 못하게 했다. 신뢰도/억제/근거 오류/단일 작업 검사와 원문 전체의 명시적 명령 확인을 함께 통과해야 생성 호출을 생략한다. 단순 편집도 후보로만 저장하며 상담 모드에서는 바로 편집하지 않는다.
- 실제 Windows Needle 실행기의 명령줄 인자에서 한국어가 손상될 수 있음을 확인해 UTF-8 localhost 요청으로 전달한다. 실행기의 수신 주소가 127.0.0.1인 것을 확인했고, 작업마다 별도 임의 포트와 프로세스를 사용한다. 실행기는 완료/오류/취소 시 종료된다.
- 실제 판단 시험에서 영어 `Set the stroke width to 70.`는 신뢰도 약 0.87로 약 1.2~1.7초에 빠른 후보를 만들었다. 한국어 3개 예제는 낮은 신뢰도, 잘못된 호출 또는 파싱 불가 응답이 발생했다. 실패를 성공으로 기록하지 않고 원문 전달로 처리하며 `artifacts/decision-live.json`에 원 응답/오류를 보관한다. 현재 한국어 가속 효과를 보장하지 않아 시험 기능/기본 꺼짐으로 제공한다.
- GPU UI 15개 기본 시나리오와 실제 판단 경로 2개를 통과했다. 공통 옵션 클릭·디스크 저장·Anthropic 선택과 독립 유지, 접근 불가능한 API 주소에서도 Needle만으로 A 획 굵기 70 후보 생성, 한국어 판단 실패 후 Gemma로 전달해 굵은 A 후보 표시를 확인했다. 화면은 `qa-decision-settings.png`, `qa-decision-fast-live.png`, `qa-decision-gemma-live.png`이다. 모두 실제 결과와 모의 UI 검증을 구분한다.
- Gemma 실제 UI 시험은 EmbeddingGemma 파일이 없는 별도 `artifacts/gemma-only-verification/`에서 수행했다. 운영 프로젝트 파일과 API 키를 사용하지 않았다. API 전송은 모의 서버에서 두 계약의 원문/이미지 동의 보존과 꺼짐/실패/불확실 경로를 검증했으며 실제 외부 유료 API는 호출하지 않았다.

## 후보 검증 범위 정정

- 이전에 제시한 `candidate-check-ai-candidates.png`의 A → 웃는 얼굴은 AI가 생성하거나 추천한 결과가 아니다. `ai-candidates`/`ai-candidate-accept` UI 시험이 기본 프로젝트의 웃는 얼굴 데이터를 A의 후보로 직접 주입했다. 해당 화면으로 확인한 것은 후보 전달·표시·채택뿐이며, 글자 정확도 통과 근거로 사용할 수 없다.
- 모의 후보를 같은 A의 획 굵기 변경 예제로 교체했다. 시험용 비교 화면에 모의 후보인지 실제 내장 AI 응답인지 표시하고, 자동 검증 완료 메시지도 UI 동작에 한정한다. 이 표시는 `ui-qa` 전용이며 일반 실행 파일에는 포함되지 않는다.
- 의미 정확도의 판정 기준: 별도의 그림 교체 요청 없이 A를 그려 달라는 요청에 웃는 얼굴이 반환되면 실패다. 화면이 표시되고 채택 버튼이 작동하는 것, 도형이 비어 있지 않은 것만으로 생성 품질을 통과시키지 않는다. 실제 요청과 결과를 함께 보고 대상 글자·지역 자형·요청 스타일을 따로 확인한다.
- 현재 공통 후보 검사는 데이터 형식과 보이는 픽셀 유무를 검사하며, 모든 로컬/외부 모델의 문자 의미를 자동 판독하는 검사가 아니다. 로컬 글자 생성 경로는 선택한 텍스트의 공개 자형을 구성하지만 이것도 모든 요청 스타일의 정확성을 보장하지 않는다.
- 정정 후 모의 후보 표시·채택/실행 취소/다시 실행·설명만 반환된 오류 처리의 3개 UI 시나리오를 재검증했다. 실제 내장 AI에 `A를 굵고 둥근 고딕체로 정확하게 그려줘.`를 요청해 반환된 굵은 A를 화면에서 직접 확인했다(`artifacts/candidate-scope-ai-typography-live.png`). 이 사례는 A의 식별과 굵은 고딕 형태를 확인한 것이며, 둥근 정도 등 모든 스타일 요구나 전체 문자 범위의 합격 판정은 아니다. 모든 기능을 포함한 clippy 경고 검사도 통과했다. 버전은 0.1.0을 유지한다.

## 0.1.0 내장 AI 글자 형태 개선

- 기존 E2B Q4가 글자 전체 좌표를 생성하던 경로에서 A·B·가·한·あ·永를 동일 요청으로 실제 생성했다. 대부분 막대/꺾인 선/사각형으로 출력됐고, 굵은 획 요청에도 stroke 값은 2~5였다. 원 응답은 `artifacts/quality-before/`에 보관한다.
- 글자는 AI가 스타일 계획을 만들고 Rust가 정확한 공개 자형을 구성하도록 변경했다. Noto Sans CJK/Serif CJK 가변 OTF와 Single Day를 리비전·SHA256 고정으로 포함한다. Noto의 65,535글리프 가변 TTF는 현재 ttf-parser의 loca 파싱에서 윤곽을 읽지 못하는 현상을 확인해 CFF2 OTF로 교체했고 실제 윤곽·가변 굵기 검사를 통과했다.
- 같은 여섯 요청의 실제 로컬 결과를 시각 비교했다. 수정 후 모두 해당 글자로 읽히며 weight=650, width=100, roundness=80으로 일관된 스타일을 반환했다. 수정 전 약 20~32초, 수정 후 약 14~16초였다. 단일 PC의 순차 실행 결과이며 일반 성능 보장은 아니다. 원 응답은 `artifacts/quality-after/`, 전후 비교는 `artifacts/quality-comparison.png`이다.
- 실제 로컬 모델이 얇은 명조체 요청에 serif/weight=200, 손글씨 요청에 handwritten을 선택했다. 현재 그림 보존 요청은 최초 시험에서 glyph로 잘못 분류해 지시문과 예시를 보완했다. 재시험에서 current/stroke=70을 반환하고 원래 두 선의 좌표를 보존하며 굵기를 모두 70으로 바꿨다(`artifacts/quality-styles-v2/`).
- 윤곽선의 방향과 내부 빈 공간을 보관하는 레이어 형식을 추가했다. O의 내부 공간이 단색·컬러·비트맵 TTF 출력 후에도 비어 있는지 검사했다. 가변 굵기·너비·기울기·서체 변경, 한글/영문/가나/한자/문장부호 17개 예제와 분해 악센트, 한국어/일본어 曜의 지역 자형도 검증했다. 한글 11,172자 전체의 기본 자형 포함 여부를 검사했다. 알려진 자형이 없는 문자는 임의의 다른 문자로 대체하지 않고 오류를 표시한다.
- GPU UI 14개 시나리오 통과. 새 윤곽 후보의 표시·채택·출처 보존·실행 취소/다시 실행·저장 후 읽기를 포함한다. `artifacts/qa-ai-typography.png`에 채택 후 비교 화면을 보관했다.
- 최종 지시문으로 여섯 글자를 재생성해 모두 고딕/weight=650으로 생성되는 것을 확인했다(`artifacts/quality-final/`). 빌드와 동시 실행한 재시험은 약 15~25초였다. 실제 앱의 생성 버튼 → 로컬 모델 → 자형 후보/출처 저장 → 비교 화면 표시도 통과했다(`artifacts/qa-ai-typography-live.png`). 자동 테스트는 총 40개이며 모든 기능을 포함한 clippy 경고 검사도 통과했다.
- 후보 출처가 채택한 글리프와 출력 보고서로 전달되고 폰트 name 테이블에 OFL 전문이 들어가는 것을 검사했다. 앱 버전과 모델 파일은 기존 **0.1.0 / E2B Q4**를 유지한다. 손글씨 자형은 제공 글꼴의 범위/기본 굵기를 따르고, 그림문자는 기존 자유 도형 생성 경로를 유지한다.
